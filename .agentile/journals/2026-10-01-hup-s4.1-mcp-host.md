# HUP-S4.1: an MCP host that assumes every server is a stranger

The WP asked for an MCP client per configured server, stdio and HTTP, with tools
mapped into the agent loop. The interesting decisions were not about the protocol;
they were about what a host owes the member when the thing on the other end of the
pipe is someone else's code.

**The spec we target is not the spec we could read.** The planset names the
2026-07-28 revision (stateless, `_meta`, Tasks, URL elicitation). The only local
material on it is our own readiness note in citrate-memories, which summarises the
changes but is not the text. Our own servers still speak `initialize`
(mem-mcp at 2024-11-05, the explorer at 2025-06-18). So the host speaks the
handshake-based protocol it can be tested against, accepts three known versions,
and refuses anything else at `initialize` instead of half-speaking a newer one.
Tasks and URL elicitation are listed as not done rather than shaped from memory.

**Annotations are hints; trust is not negotiable.** `readOnlyHint` decides whether
a tool is offered at all (write tools are off unless the allowlist entry says
otherwise), but no annotation can make MCP output trusted. The first MCP result
taints the session, and because the sidecar has no way to put a call in front of
a person, the loop then declines effectful MCP calls instead of running them. That
is stricter than it will eventually need to be; HUP-S4.4's review screen and an
approval path in core are where it loosens, with a person in the loop.

**Robustness is mostly about not trusting the stream.** A bounded line reader (an
oversized line is attributed by a cheap id scan, else every pending request fails),
skipped and counted garbage, a writer thread so a server that stops reading cannot
block a turn, stderr discarded so a chatty server cannot deadlock, and an exited
process failing its pending calls at once instead of waiting out the deadline.

**Test the real thing.** The fixture is a real stdio MCP server binary and a real
axum HTTP server sharing one message-logic file, not an in-process fake. Six
mutants (drop `env_clear`, trust MCP output, ignore `allow_write_tools`, skip the
cancel notification, accept any version, remove the size cap) were each caught.
