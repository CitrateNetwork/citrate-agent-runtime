# HUP-S2.9 (runtime half): undo checkpoints for agent file writes

Planset: citrate-core `.agentile/planset/2026-09-30-hermes-upskill/` (05_SPRINTS_AND_WPS, S2.9;
00_OVERVIEW item 15 lists "undo checkpoints for agent file writes"). Federation sprint issue #279.

## What shipped

New workspace crate `citrate-agent-checkpoints` (`agent-checkpoints/`). No new dependencies
beyond what the workspace already locks (serde, serde_json, thiserror, sha2, hex; tempfile for
tests).

- `CheckpointStore::open(app_data_dir, Config)`: one process per directory (OS file lock),
  directory mode 0700 on Unix, crash recovery on open (temp files removed, in-flight steps marked
  `Interrupted`, unreferenced blobs collected).
- `begin_step(session, granted_folder, &[Change])` snapshots the prior state of every path before
  the tool writes: regular files into a content-addressed blob store (SHA-256, deduplicated,
  permission bits kept), symbolic links as their target text (never followed), absent paths as
  absent. Snapshot and manifest are fsynced before it returns. `Step::commit` records the
  post-change state; `Step::abort` or dropping the step marks it `Interrupted`.
- `undo_step` and `undo_session` restore exactly: overwritten files get their bytes and mode back,
  deleted files are recreated, created files are removed (with the directories the step created,
  if still empty), renames are reversed including an overwritten destination. Every restore is a
  temp sibling plus rename.
- Conflict detection: a path must be in the step's post-change state, or already back in its prior
  state; anything else refuses the undo with `Error::Conflict` and changes nothing. A session undo
  is checked as a whole (virtual view across steps) before anything is restored. Blob hashes are
  verified before any restore and again while copying.
- Size: `max_file_bytes` (default 64 MiB) refuses a bigger file with a reason naming the path, size
  and cap; `max_store_bytes` (default 512 MiB) prunes least recently used session first, oldest
  step first, never a step in flight; a step that alone exceeds the store is refused; an undo of a
  pruned step reports `Error::Pruned`.
- Concurrency: operations serialized in-process; a path with a step in flight refuses a second
  step or an undo with `Error::Busy`.
- Path rules: only plain relative components (or an absolute path inside the folder); `..`, other
  roots, symlinked parent directories, directories, special files and writing through a symlink
  are refused.
- Git mode: `git_checkpoint(session, folder, message)` commits the folder's working state to
  `refs/citrate/checkpoints/<session>` via a temporary index (copy of the real index, read only),
  `add -A -- .`, `write-tree`, `commit-tree --no-gpg-sign` with a fixed identity, and a
  compare-and-swap `update-ref`. HEAD, the index, every branch and `git status` are unchanged
  (tested byte-for-byte on the index). Unchanged tree is a no-op. Works on an unborn branch and
  from a subfolder grant.

## Not done (honest)

- Not wired into any tool. The file tools (write/edit/delete/rename) adopt `begin_step`/`commit`
  in a later WP, and must run the agent-guard deny list before this store snapshots anything
  (the store copies whatever it is pointed at).
- No undo UI and no Tauri commands: that is the citrate-core half of S2.9.
- Symbolic links are restored on Unix only; on Windows a symlink step undo reports `Unsupported`.
- Restoring from a git checkpoint is not offered; git mode only records.
- Stray `.citrate-undo-*` temp siblings can remain in a granted folder if the process dies in the
  middle of a restore; the store cleans only its own directory on open.

## Decisions for the owner

- Defaults 512 MiB store and 64 MiB per file are placeholders chosen conservatively; the app may
  lower them. Planset 00 lists "default budget values" as open.
- Checkpoint commits use the fixed identity `Citrate checkpoint <checkpoint@citrate.invalid>` and
  are never signed, so they never prompt for a key and never look like member commits.
