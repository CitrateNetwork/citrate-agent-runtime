# HUP-S7.3 (runtime half): nightly anchor batch + inclusion proofs

Program: Hermes upskill (HUP), sprint S7 "Chain-native agent". Planset and sprint tracking live in
citrate-core (`.agentile/planset/2026-09-30-hermes-upskill/`, release/0.5.0-hermes-upskill);
federation issue #284. This file is the runtime-side WP record.

## Scope

New crate `agent-anchor` (`citrate-agent-anchor`) over `agent-records`: a UTC day's batch across
segment rotations, an RFC 6962 tree, a domain-separated day commitment, per-record inclusion
proofs with a verifier, a local anchor ledger, and the unsigned
`AnchorRegistry.anchor(AnchorKind.NightlyMerkle, commitment)` calldata. TLA+ `AnchorBatch`.

Shared-file touches: workspace `Cargo.toml` member, `Cargo.lock`, and `agent-records/src/merkle.rs`
(`leaf_hash` / `node_hash` made public, `retained_leaves` + `RetainedLeaf(s)` added so the anchor
crate reuses one definition of the hashing and sees where pruning stopped; behaviour unchanged).

## Not done (honest)

- Core half: anchor key and signing in the ceremony (Rule-3 ADR), the nightly schedule, the
  confirmation write-back (`mark_confirmed`), and any UI. No sidecar route calls this crate yet.
- No `AnchorRegistry` address is hard-coded; the 40204 book was cleaned for the reroll.
- Proofs need the day's records retained; after a batched day is partly pruned, `prove` returns
  `PrunedDay`.

## Decisions taken while the owner was away (conservative, reversible)

1. The anchored value is a commitment over `(v, day, first_seq, last_seq, count, tree_root)`, not
   the bare tree root, so the on-chain value names exactly what it covers and proofs bind `seq`
   to position. Changing back to the bare root is a one-line change in `BatchHeader::commitment`
   before anything is anchored.
2. A day with some records pruned before batching is reported `incomplete` and never anchored,
   instead of anchoring a root over part of the day.
3. Only closed UTC days are batched (`day < today`).

## Journal

The interesting part was not the tree; `agent-records` already had RFC 6962 with the right
prefixes. It was what "the root covers exactly that day's records" has to mean once you notice
`AnchorRegistry` keys anchors globally by value and refuses repeats. A bare root says nothing about
which day or which records it covers, so the commitment carries the day and range, and the proof
binds `seq` to its leaf index. The other edge was pruning: `agent-records` can drop old segments,
and a root over half a day would quietly claim less than it looks like. Writing the TLA+ model
first with a `Rewrite` environment action (a consistent rewrite of the whole log, the one thing
the hash chain alone cannot catch) made the ledger's `Conflict` path a modelled requirement
instead of an afterthought, and the mutation runs showed each property bites on its own once the
config holds only that property.
