## Decisions taken conservatively (for owner review)

1. Metering is always on in the sidecar (records carry no conversation content), persisted only
   where core points it. Trajectories stay off unless the member sets the env var.
2. Trajectories are exported at session close, not per turn, so a taint that arrives late still
   excludes the earlier turns. A session the app never closes is not exported.
3. `/anchor/confirm` requires the commitment the day was batched with, so a confirmation for a
   different root cannot mark a day anchored.

## Not done (honest)

- Sessions run single turns, not workflows, so no verifier events reach metering or trajectories
  yet: every turn is "unverified" and no trajectory is exported. That is the honest result.
- Nothing writes decision records yet, so `/anchor/status` lists no closed days in practice.
- D-27 measures outside the event stream are named in `notMeasured` and not collected.

## Journal

The token counts were the only piece the event stream could not carry, and the model seam had
no way to say "this call used N tokens". Adding a default method that returns no usage kept every
existing client honest by construction: anything that does not know reports unknown, which the
daily report already distinguishes from zero. The mutation pass found the one place that rule
was not pinned: a missing `completion_tokens` field could have been read as zero without any test
noticing.
