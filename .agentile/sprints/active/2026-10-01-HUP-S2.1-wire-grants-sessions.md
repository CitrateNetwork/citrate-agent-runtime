# HUP-S2.1 wiring (runtime half): folder grants in agent sessions

Planset: citrate-core `.agentile/planset/2026-09-30-hermes-upskill/` (04_FEATURES_BDD US-2.1,
05_SPRINTS_AND_WPS S2.1). Builds on `citrate-agent-grants` (fan-out 3). Federation sprint
issue #279. Core half (store, Grants panel, delivery): citrate-core branch `hup/n4-grants-e2e`.

## What shipped

`agent-sidecar/src/grants.rs` (new) plus minimal session wiring:

- `POST /sessions` takes an optional `grants` field: the member's `GrantState` document, which
  citrate-core owns and stores. Validated with `FolderGrants::from_state` against the member's
  home (the sidecar's `HOME`); a refused document refuses the session.
- `POST /sessions/:id/grants` replaces a session's grant set (core calls it after every change).
  400 on a refused document, which also leaves the session with **no** grants (a refused
  update never keeps an older, broader set alive); 409 for a session opened without grants; 404
  for an unknown session; bearer-gated like every route.
- Sidecar-hosted file tools, offered only to a session opened with a document:
  `file_list`, `file_read` (UTF-8, at most 256 KiB), `file_write` (at most 1 MiB, parent must
  exist). Every path is checked through `FolderGrants::check` at the moment of use. Writes open
  the leaf with `O_NOFOLLOW` and refuse a file with other hard links. Listings leave out entries
  the agent could not read. Reads under a folder grant are trusted context; reads only full
  access covers return `ToolOutcome::Untrusted` and taint the session (HUP-S2.7).
- Toolchain (HUP-S6.3): with a document, the project folder must be covered by live read and
  write folder grants; `CITRATE_HERMES_TOOLCHAIN_ROOTS` is ignored for that session and the run
  happens in the canonical folder. Without a document nothing changes.
- Tool names `file_list` / `file_read` / `file_write` are reserved in sessions with grants.

Nothing here holds a key or signs (Rule 3). No new dependency beyond `libc` (unix, already in
the lock) and the workspace's own `citrate-agent-grants`.

## Review fixes (adversarial review, 2026-10-01)

- A grant row whose folder is in a deny location is now set aside (`GrantSummary::ignored`)
  instead of refusing the member's whole document. Core's early refusal list is shorter than the
  deny list, and a revoked row stays in the document, so one such row used to refuse every new
  session and strip the grants from every open one. The row could never allow anything, so
  dropping it narrows nothing. Test:
  `a_grant_rooted_in_a_deny_location_grants_nothing_and_does_not_refuse_the_rest` (red before).
- `with_grants_the_toolchain_needs_read_and_write_folder_grants` now also covers a write folder
  grant with only full access for reading (kills the mutant that drops the read-kind check).
